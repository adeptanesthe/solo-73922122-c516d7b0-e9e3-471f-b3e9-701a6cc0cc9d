# 卡纸预警提前量核定 · 历史回放

印刷班组用历史记录核定：卡纸预警最多能留出多少处置时间。

上传逐分钟模型分数 CSV，填写告警阈值、有效提前量上限 U、至少命中次数 K，并录入
若干次卡纸的可能时刻区间；系统求出**任一组卡纸时刻组合都至少命中 K 次**的最大
整数提前量 L（1≤L≤U）。若 L<U，列出 L+1 档不足 K 次的一组卡纸时刻及其最佳配对；
若连 L=1 都不达标，则提示"无法承诺"并给出 L=1 档反例。

## 规则约定

- **告警**：每段连续达标（分数 ≥ 阈值）只在首分钟产生一条告警。
- **卡纸**：每次卡纸的可能时刻为一个闭区间（至多 10 个分钟号），最多 20 次，
  各区间互不重叠；一组卡纸时刻 = 各区间各取一分钟。
- **配对**：给定 L，只用卡纸前 L～U 分钟的告警做一对一配对（一张告警、一次卡纸
  各至多配一次），每组组合按最大配对数计命中。
- **更正即撤下**：重新上传数据或修改参数/区间后，旧结论立即撤下（页面"历史结论"
  区可见），按新区间重算。

## 启动（Docker Compose）

```bash
docker compose up --build
# 打开 http://localhost:5000
```

## 网页操作样例（实测）

1. 首页点 **下载示例 CSV**（或用仓库根目录的 `sample_data.csv`，720 行，分钟 1~720），
   在"① 上传"处选择该文件上传。页面提示：
   `已加载 sample_data.csv：720 行，分钟 1 ~ 720，分数 33 ~ 91。`
2. 在"② 填写参数与卡纸记录"中输入：
   - 告警阈值：`80`　有效提前量上限 U：`90`　至少命中次数 K：`5`
   - 卡纸区间（每行一段）：
     ```
     125-130
     250-254
     370-374
     480-484
     600-604
     705-709
     ```
3. 点 **核定最大可承诺提前量 L**，"④ 核定结论"显示（实测）：
   - **可承诺：L = 60 分钟**。任意卡纸时刻组合至少命中 **5** 次 ≥ K=5；
   - **L=61 档反例**：组合 `[125, 250, 370, 480, 600, 705]` 只命中 **4** 次，
     最佳配对为 卡1←告警60（提前65）、卡2←告警175（提前75）、卡3←告警301（提前69）、
     卡5←告警535（提前65），卡4、卡6 未配对；
   - "③ 分数回放"图中：蓝色折线为分数、红点为告警、橙色带为卡纸区间、
     紫色虚线为反例时刻、绿色弧线为配对；拖动滑杆可逐分钟回放分数与告警。
4. 把 K 改为 `7` 再核定（卡纸共 6 次，不可能命中 7 次）：显示
   **无法承诺：连 L=1 档都存在组合命中不足 K=7 次（下例仅命中 6 次）**，并列出
   L=1 档反例组合与最佳配对。
5. 修改任一区间（如把 `125-130` 改为 `126-130`）重新核定：旧结论立即移入
   "⑤ 历史结论（已撤下）"，标注撤下原因，当前结论按新区间重算。

## 输入格式与校验

- **CSV**：两列 `分钟号,整数分数`（可含表头）；分钟号连续（步长 1）；最多 3000 行。
- **区间**：每行 `起-止` 或 `起 止`（单分钟写一个数）；≤20 段，每段 ≤10 个分钟号，
  互不重叠（共享端点也算重叠）。
- **参数**：阈值为数值；U、K 为 ≥1 的整数。

## 算法说明（为何不枚举时刻组合）

20 段 × 10 个分钟号的组合高达 10^20，逐一枚举不可行。本工具利用"区间互不重叠"
的结构：

- 任一组合下窗口 `[t_i-U, t_i-L]` 的左右端点均按下标递增。由 König 定理，
  最大配对数 = 最小顶点覆盖 = `min_S (|S| + 剩余窗口并集覆盖的告警数)`；
- 端点有序使"并集覆盖"可沿下标分解（每个窗口只贡献超出前一保留窗口右端点的
  新告警），于是 `min_组合 最大配对数` 化为**最短路 DP**：按序处理每张卡纸，
  要么支付 1 删去，要么为其选时刻（≤10 种）并支付新增覆盖告警数；
- 窗口随 L 增大而收缩 ⇒ 保证命中数关于 L 单调不增 ⇒ 二分最大的可行 L。

整体复杂度 O(log U · m · q²)（m≤20 为卡纸数，q≤10 为区间分钟数），满负荷
（3000 行数据、20 段区间、U=3000）实测单次核定约 0.2s。正确性由 `tests.py`
中小规模暴力枚举全部组合的结果交叉验证。

## 已知限制

- 会话数据保存在单进程内存中，重启即清空；多副本部署需改用共享存储。
- 告警去重依赖"分钟号连续"的校验，缺口数据会被拒绝而不做插值。
